# 河北基地运营管理平台 · 全岗位作战中枢

面向规模型呼叫中心的可运行全栈产品基线。系统以岗位目标、实时差距、工作提醒和跨岗位 PDCA 为主线，让运营、客服、质检、培训与 HRBP 在同一业务状态上协同，并保留全过程记录。当前版本可直接用于业务验证和数据适配开发；正式生产部署仍需完成文末列出的认证、数据库和集成工作。

## 当前已实现

- 今日作战：首页与预警中心使用同一份工作流状态，展示优先事项、指标和动态任务
- 四类预警：员工异常、话务异常、投诉超时和质量趋势
- PDCA 状态机：主管确认 → 班长执行并提交证据 → 主管验证 → 经理/总监闭环、退回或升级
- 本地持久化：事件、任务、通知和审计写入 JSON，刷新页面不会丢失
- 业务复位：顶部复位按钮可恢复演示业务基线并同步备份，但不会重置账号、密码和角色权限
- 多角色视图：运营总监、客服经理、客服主管、客服班长、客服专员、质检、培训和HRBP
- 系统管理：用户账号、岗位资料、角色分配、账号启停、安全密码重置、角色外模块配置和左侧菜单权限；配置由服务端持久化并执行RBAC校验
- 业务数据隔离：全部业务、报表和PDCA接口要求有效登录会话；普通账号不能伪造岗位，状态响应按岗位过滤任务、通知、培训、HRBP和审计数据
- 内置角色：系统管理员、运营总监、客服经理、客服主管、客服班长、客服专员、质检专员、培训主管和HRBP经理
- 班前会：标准 15 分钟议程和真实倒计时
- 班组看数：人员状态、产能、CPH、满意度、小休占比和趋势
- 组织与排班：统一人员、班次和班组覆盖数据；员工调班/请假经班长、主管、HRBP闭环，主管跨班调度经经理审批后自动更新覆盖
- 主管生产控制塔：完整区域排班计划按班组识别缺口；技能路由方案受调出侧95%安全线约束，经经理审批后由主管执行并回填实际接通率，未达目标自动返回改进
- 总监经营治理：经理提交收入、成本、毛利预测和合同续约材料，总监批准或退回；经营会议可一键归档并将行动下发经理/主管PDCA，跨部门事项由目标岗位回执后再由总监验收
- RPA报表员：支持河北回流10010、北方中心10015、联通在线400项目选择；10015可预览、运行并下载真实CSV，运行和下载均持久化留痕
- 四类报表：班组晨报、基地运营日报、个人绩效周报和月度经营分析
- 晨会任务单：员工通报宽表可一键创建持久化PDCA任务，自动下发班长并进入执行、主管验证及逐级升级流程
- 质检协同：质检发起协同单后自动进入班长PDCA，班长提交辅导证据，质检复检可通过或退回
- 员工求助：客服专员发起支持请求，班长处理并回传结果，由员工确认解决或重新打开
- 培训日报：培训主管一键发送，运营经理收到提醒并查阅批示，结果自动回执培训岗
- 培训生产流程：岗前班六阶段持久化管理，学员个人目标/差距/复测/能力档案，通关和档案关闭受服务端目标门槛约束；岗中专项达标后由质检独立验效，可关闭或退回补训并提醒经理
- 学习成长闭环：培训岗维护题库版本、讲师教室和课程场次；员工按个人指标Gap完成学习与考试，达标后由班长使用录音和指标验证业务改善；员工建议与30/60/90日成长评估均有受理、回执和留痕
- 质检生产流程：分层抽检计划与覆盖率/及时率门槛、录音质检证据、员工/班长申诉、质检校准、案例库；校准未达标自动生成培训纠偏专项，员工侧可查本人记录和申诉进度
- 人员稳定：HRBP创建高流失风险沟通任务，可自主解决或升级经理PDCA；经理关闭后回传HRBP确认备案
- HRBP生产流程：编制与招聘漏斗、补员方案经理审批、培训通关名单自动转入新工入列、员工转调离、劳动关系、人员成本预测及结构化访谈均持久化；审批生效后自动更新组织与人员主数据
- 全局搜索：点击顶部搜索或按 `⌘ K` / `Ctrl K` 搜索员工、预警、指标和模块
- AI作战助手：服务端代理 DeepSeek 基础模型，支持多轮聊天，并自动携带当前岗位、页面、核心指标和待办数量作为作战上下文
- AI行动闭环：各岗位可把对话建议生成可编辑的行动草案；必须由本人确认后才会创建PDCA任务，并按“本岗位执行 → 上级岗位对照目标验收 → 关闭或退回整改”流转

## 技术栈

- 前端：React 18、TypeScript、Vite、Recharts
- 后端：Node.js `node:http`
- 存储：本地 JSON 主文件、备份文件和原子写入
- 部署：Node.js 或 Docker

## 本地开发

需要 Node.js 18 或更高版本。

```bash
npm install
```

开发模式需要两个终端。

终端 1，启动业务 API：

```bash
npm run api
```

终端 2，启动 Vite：

```bash
npm run dev
```

前端默认运行在 `http://localhost:5173`，`/api` 请求会代理到 `http://localhost:4174`。

### 配置 DeepSeek

推荐直接在平台中配置：

1. 切换到“运营总监”角色，以系统管理员身份进入平台。
2. 打开“系统管理 → AI模型配置”。
3. 填写 DeepSeek API Key，选择模型。
4. 点击“保存并测试连接”。

保存后无需重启业务 API，所有岗位的AI作战助手立即共用这套模型连接；各岗位聊天记录相互隔离。Key保存在 `server/data/ai-config.json`，文件权限限制为当前系统用户可读写，且已加入 `.gitignore`。

也可以使用服务器环境变量作为首次配置或部署兜底。复制示例配置：

```bash
cp .env.example .env
```

```ini
DEEPSEEK_API_KEY=sk-your-deepseek-api-key
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

通过 `.env` 配置时需要重新启动业务 API。通过系统管理页面配置时不需要重启。API Key 只由 Node 服务读取，不会返回给浏览器。

相关接口：

- `GET /api/ai/status`
- `GET /api/ai/settings`
- `PUT /api/ai/settings`
- `POST /api/ai/test`
- `POST /api/ai/chat`
- `POST /api/ai/action-drafts`（生成草案，不写入任务）
- `POST /api/ai/action-drafts/execute`（人工确认后创建任务）

AI接口均校验登录会话和当前岗位上下文。系统管理员可在授权范围内模拟岗位；普通账号只能以自身岗位调用。行动草案的标题、问题、目标、责任人、截止时间和达成标准可在确认前修改，AI不会自动下发任务。

### 用户与角色权限

用户、角色及权限审计保存在 `server/data/access-control.json`，文件权限限制为当前系统用户可读写并已加入 `.gitignore`。密码不会返回浏览器，服务端使用随机盐和 `scrypt` 保存密码哈希；重置密码后会强制首次登录改密。登录态由8小时有效的HttpOnly、SameSite=Lax Cookie承载，系统管理接口只认服务端会话中的用户身份，不接受前端伪造操作人。服务端会拦截越权操作、重复工号、重复角色编码、删除内置角色、删除仍有关联账号的角色，以及停用最后一个系统管理员。

相关接口：

- `GET /api/access`
- `PUT /api/access/users`
- `POST /api/access/users/:userId/action`
- `PUT /api/access/roles`
- `DELETE /api/access/roles/:roleId`
- `POST /api/auth/login`
- `GET /api/auth/session`
- `POST /api/auth/change-password`
- `POST /api/auth/logout`

### macOS 一键启动

也可以双击 `启动平台.command`。脚本会检查 Node.js 和本机依赖，启动 4174 API 与 4173 前端，并自动打开浏览器。

## RPA 数字员工 · 报表员

RPA报表页面以三个项目为统一入口：

- 河北回流10010：模板和字段架构就绪，等待配置项目数据适配器
- 北方中心10015（10015升投）：本轮已接入离线样本快照，可真实运行和下载
- 联通在线400：模板和字段架构就绪，等待配置项目数据适配器

10015口径来自用户提供的 `15升投运营日报-0720.xlsx` 与 `10015队列晨会日报_20260719.xlsx`。前者约284MB且包含大量现代公式与既有缓存错误，平台运行时不会复制、打开或重算原文件；服务端只保存已核验的指标快照、来源工作表和质量提示。晨会口径优先参考 `话务透视`、`归档透视`、`效能`、`申诉拦截`、`人员信息` 与 `工号串用处理` 等事实表。

报表运行会在 `server/data/generated` 生成带UTF-8 BOM的CSV，Excel和WPS可直接打开。每次运行记录输出行数、来源、耗时、文件大小和质量提示；每次下载会增加下载次数，并写入专用下载记录和全局审计。顶部演示复位会删除生成文件和全部报表运行/下载留痕。

当前报表接口：

- `GET /api/reports/catalog`
- `GET /api/reports/preview`
- `GET /api/reports/runs`
- `POST /api/reports/runs`
- `GET /api/reports/runs/:runId`
- `GET /api/reports/runs/:runId/download`

## 生产化边界

当前版本已经具备可交互、可持久化、可构建部署的产品骨架，但在正式承载生产业务前仍需完成：

- 尚未连接真实 MySQL 或业务系统；运营数据和预警证据为脱敏模拟数据
- AI助手已接入DeepSeek；未配置 `DEEPSEEK_API_KEY` 时聊天入口会明确提示待配置，不会使用伪造模型回答
- RPA报表员已经能够从离线样本快照生成真实CSV，但尚未实现动态上传解析、Microsoft Excel公式重算、企业微信推送或10010/400真实数据适配
- 工作流使用 JSON 原子写入与备份持久化，适合单机验证；生产环境需要迁移至支持事务、并发和多租户的数据库
- 当前已具备本地账号登录、首次改密和服务端会话；生产部署仍需接入企业统一身份认证、MFA、登录限流、密码复杂度策略和集中式会话存储
- 目前会话保存在单个Node进程内，服务重启后需重新登录；多实例部署应迁移到Redis等共享会话存储
- 左侧菜单权限同时用于界面可见性和报表/系统管理接口RBAC；业务写接口校验登录账号与请求岗位一致，普通账号无法通过修改请求参数模拟其他岗位
- 当前数据隔离以岗位为边界；生产接入组织主数据后，还需增加项目、区域、班组和员工本人四级数据范围授权
- 组织与排班已具备持久化流程和人力保护线，但人员、班次、技能和覆盖数据仍是脱敏样本，正式使用时需连接WFM、考勤和HR主数据
- 主管与总监治理流程已经持久化并具备服务端门槛；正式使用时需把技能路由接入ACD/WFM，把预算、合同、结算和客户沟通接入财务及合同系统

真实数据接入后，应增加只读数据适配层；班前会、面谈、培训、预警处置和 PDCA 任务需要独立业务表。正式部署还需补充认证、数据库、审计归档、限流和权限安全测试。
